# CYD: ESP32-2432S028R "Cheap Yellow Display"

Package: [`cyd-2432s028.yaml`](cyd-2432s028.yaml)

- ESP32-WROOM-32 (ESP32-D0WD-V3, rev 3.1), 4 MB flash, **no PSRAM**
- 2.8" 320×240 SPI TFT
- XPT2046 resistive touch, on its **own** SPI bus
- CH340 USB-serial (shows up as `USB-SERIAL CH340`)
- RGB LED, LDR, speaker connector, SD slot (not used here)

Units in use: two, bought as a pack, both the twin-USB ST7789V revision.

## Revisions: which display controller?

| Board | Controller | `display_model` |
|---|---|---|
| One micro-USB socket | ILI9341 | `ESP32-2432S028` |
| USB-C **and** micro-USB | ST7789V (ours) | `ESP32-2432S028-7789` (default) |
| USB-C and micro-USB (rarer) | ILI9342 | `ESP32-2432S028-9342` |

The two twin-USB variants look the same from outside. Flash with `-7789`
first. A white screen, a negative-looking image or noise means try `-9342`.
These are ESPHome's built-in `mipi_spi` presets. They set the controller,
CS=GPIO15, DC=GPIO2 and 40 MHz SPI.

## Pinout

| Function | Pin | Notes |
|---|---|---|
| TFT SCLK / MOSI / MISO | 14 / 13 / 12 | GPIO12 is a strapping pin (harmless warning) |
| TFT CS / DC | 15 / 2 | set by the preset |
| TFT backlight | 21 | PWM (ledc) |
| Touch CLK / MOSI / MISO | 25 / 32 / 39 | separate SPI bus; 39 is input-only |
| Touch CS / IRQ | 33 / 36 | 36 is input-only, no internal pull-up (board has one) |
| RGB LED R / G / B | 4 / 16 / 17 | **active LOW**, very bright |
| LDR | 34 | see quirks: not usable |
| Speaker | 26 | not used |

## Orientation

Landscape with the **USB sockets on the right** is LVGL `rotation: 90`. The
display itself stays at rotation 0: ESPHome refuses display-level rotation
when LVGL is used.

## Calibrating touch

Only needed if a project has touch targets (a "tap anywhere" project can use
the defaults). Resistive panels vary per unit, so measure each one.

Use [`tools/touch-calibration/`](../tools/README.md#touch-calibration):

1. Flash `cyd-touch-calibration.yaml` (test card, logs raw touches).
2. With USB on the right, tap about 5 mm in from each corner, then the centre.
3. `calc_calibration.py` extrapolates to the edges and prints
   `touch_x_min/x_max` (raw X runs **top→bottom**) and `touch_y_min/y_max`
   (raw Y runs **left→right**) for the device file.
4. Check with the light-panel demo: each tap should hit the tile under the
   finger.

The board file's `transform: mirror_x: true` is needed with rotation 90.
Without it, taps on the top row land on the bottom row.

Measured: light-panel unit x 472–3820, y 170–3879. The typical values in the
board file are 280–3860 / 340–3860.

## Quirks found on the real hardware

- **The LDR can't be used for auto-brightness.** Room light and full darkness
  both read ~0.075 V at 0 dB attenuation (the ADC's floor). Only a phone torch
  moved it, to ~0.11 V. At 12 dB it's even worse: it sits at the 0.142 V floor.
  The divider makes it too insensitive for room light. The bus display dims by
  the sun's elevation from HA instead.
- **Backlight gamma must be 1.0.** With gamma correction, a "night minimum" of
  8% became ~0.4% PWM duty and the screen looked switched off.
- **Backlight `restore_mode: ALWAYS_ON`.** Restoring the last state brought the
  panel back dark after a replug, because it had gone to sleep before being
  unplugged.
- **Mid-flash USB dropouts** ("A device attached to the system is not
  functioning", then "Access is denied"). Unplug, replug and flash again. Moving
  the board during a flash caused it.
- **Opening the serial port resets the board** by default (DTR/RTS). To read
  logs without a reset, open it with DTR and RTS de-asserted.
- **Memory:** a full 16-bit framebuffer doesn't fit without PSRAM. With LVGL,
  `mipi_spi` needs no framebuffer of its own, and LVGL's `buffer_size: 25%`
  is enough. Both current projects use ~28% RAM and 60–67% flash.
- Harmless boot warnings: GPIO12 strapping pin, "Touch Polling Stopped" (the
  IRQ pin is in use), and hints about `minimum_chip_revision` and
  `sram1_as_iram`.
